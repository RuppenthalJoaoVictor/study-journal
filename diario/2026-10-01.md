# 2026-10-01 — Python: tipagem estática e `mypy`

## 🎯 Objetivo

Entender o que é tipagem estática em Python e como configurá-la em um projeto
real, já que toda vez que abro um editor as anotações de tipo aparecem sem
explicação.

## 🧠 O que aprendi

### Anotação de tipo não altera o comportamento

A anotação é apenas uma descrição que o interpretador **ignora** em tempo de
execução. Isso significa que ela não protege o programa em runtime — apenas
permite que ferramentas externalas verifiquem antes.

```python
def somar(a: int, b: int) -> int:
    return a + b

# Funciona em runtime, mas está errado para quem lê:
def somar(a: int, b: int) -> int:
    return str(a) + str(b)
```

A segunda função roda. O erro só aparece quando o `mypy` analisa.

### O `Any` se propaga silenciosamente

Um único `Any` em um ponto do código contamina o retorno de tudo que o consome.

```python
from typing import Any

def ler_json() -> Any:      # <- ponto de origem
    ...

def total() -> int:
    dados = ler_json()      # <- 'dados' é Any
    return dados["total"]   # <- o mypy não pode provar que é int
```

Por isso `warn_return_any = true` no `mypy.ini`: é o que força o erro a
aparecer no ponto de origem em vez de silenciosamente anos depois.

### `Any` explícito é melhor que `Any` implícito

```python
from typing import Any

def processar(valor: Any) -> str:
    return str(valor)  # aceito: estou declarando que não me importo com o tipo
```

Escrever `Any` de propósito é uma decisão. Acabar com `Any` sem querer é um bug.

## 🧱 O que travou

- **Por que `mypy` não reclamou de `ler_json()`?** Demorei para entender que
  `json.loads()` retorna `Any` e que `Any` é compatível com tudo — o `mypy`
  estava certo em não reclamar. O problema era meu `warn_return_any`, que só
  funciona quando ligado explicitamente.
- **`Optional[X]` vs `X | None`.** No Python 3.10+ a sintaxe `X | None` é
  melhor, mas `Optional[X]` ainda aparece em muita documentação antiga e me fez
  achar que eram coisas diferentes. São idênticas.
- Instalei `mypy` pelo `pip install` do sistema e ele ignorou o `pyproject.toml`
  do projeto. Resolvi usando `.venv` sempre.
